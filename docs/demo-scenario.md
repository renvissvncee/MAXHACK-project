# Демо-сценарий на двух аккаунтах MAX

Эти данные вводятся двумя реальными тестовыми аккаунтами. Они не загружаются в production автоматически: фиктивный MAX ID сломал бы доставку уведомлений и контакт после мэтча. Опциональный синтетический seed-набор из README нужен только для наполнения каталога/UI и не заменяет этот сквозной MAX-сценарий.

## Аккаунт 1 — хозяин

- Имя: Алина
- Город: Казань
- О себе: «Люблю архитектуру, пешие маршруты и татарскую кухню. Покажу город без туристической спешки».
- Интересы: архитектура, прогулки, кухня
- Предложение: «Уютная комната рядом с центром»
- Кратко: «Отдельная комната, до Кремля 15 минут пешком»
- Описание: «Светлая комната в квартире. Можно пользоваться кухней и рабочим столом»
- Гостей: 2; тип: комната
- Даты: выбрать период, включающий день демо
- Удобства: Wi-Fi, кухня, рабочее место
- Правила: не курить, предупреждать о времени прихода

## Аккаунт 2 — гость

- Имя: Михаил
- Город: Москва
- О себе: «Еду в Казань на выходные, интересуюсь историей города и локальной кухней».
- Интересы: история, фотография, путешествия
- Текст запроса: «Привет! Буду в Казани на выходных. Буду рад познакомиться и узнать ваши любимые места».

## Порядок показа

1. Хозяин создаёт профиль и предложение.
2. Гость ищет Казань по датам и отправляет запрос.
3. Хозяин открывает MAX-уведомление, попадает во входящие и принимает запрос.
4. Гость открывает уведомление, видит решение и контакт.
5. Один из участников оставляет отзыв; второй проверяет третье MAX-уведомление и обновлённую репутацию.

Для ветки отклонения создайте второй запрос с новым `clientRequestId` и отклоните его.
