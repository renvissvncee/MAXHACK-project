# Problem pitch

**Hospitality exchange уже существует — например, Couchsurfing.**

Мы исследуем, как адаптировать этот формат для российских поездок внутри MAX.

Для путешественника важно не только найти место для проживания, но и **понять, кому он доверяет**. Для хозяина — **понимать, кого он приглашает в свой дом**.

В 15 интервью доверие и достаточность информации о человеке стали важными темами при принятии решения о взаимодействии.

**Проблема, которую мы исследуем: как снизить неопределённость между двумя незнакомыми людьми до того, как они решат взаимодействовать.**

# Solution pitch

**Мы объединяем ключевой сценарий hospitality exchange внутри MAX:**

**поиск → профиль → репутация → запрос → предварительное одобрение → общение.**

Пользователь получает структурированную информацию о человеке, может изучить отзывы и принять решение до начала взаимодействия.

На уровне MVP мы проверяем главное поведенческое действие:

> **Получает ли отправленный запрос предварительное одобрение хозяина?**

Digital ID рассматривается как **дополнительный внешний сигнал подтверждения личности**: пользователь может самостоятельно предъявить его другому человеку. Автоматической проверки наличия Digital ID через MAX API в нашем сценарии нет.

**Наша задача на этом этапе — не доказать весь рынок, а проверить, работает ли сам сценарий и помогает ли он людям перейти от поиска к реальному взаимодействию.**
